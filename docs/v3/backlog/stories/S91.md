**Gap:** S90 trains a next-pitch model, but nothing runs it during a game or shows it. The owner (2026-10-29) chose what a viewer sees — *"Odds by pitch type + likely location"* — and who: *"Paid tier only"*.

**Impact:** Before S91, a paying fan sees each pitch only once it's thrown. S91 impact: before every pitch they see the odds of each pitch type and where it's likely headed, and afterwards whether the call was right.

**Acceptance criteria** (checks `scripts/verify-S91.sh` performs)

1. **Ingest predicts, clients read** (ADR-002): when the live game's state changes, the server runs `predictNextPitch` for the coming pitch and stores it with the game state, versioned like every other update; the browser never runs the model and never calls MLB.
2. **Paid tier, enforced on the server:** the prediction is in the game payload only for a session whose entitlements include it (`packages/domain` entitlements); a test shows a free or signed-out session gets no prediction field at all.
3. **The Live room shows it** as S92's frames draw it: the odds by pitch type, and the likely location on the catcher's view, in the zone's own scale (the camera from `catcher-view.ts`).
4. **After the pitch,** the room shows whether the call was right (the thrown type against the predicted odds), and BT keeps a running hit rate per game.
5. A render-count baseline (S54 helper) for one prediction update of the Live panel.
