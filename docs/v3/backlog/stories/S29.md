**Gap:** S27 commits `openapi/bt-api.v1.json` as a derived artifact that **nothing consumes**. `oasdiff` only compares the spec against its own previous self, never against reality — so a route the emitter under-specifies (a dropped field, wrong nullability, a widened union) passes the gate forever and stays wrong. Nothing forces the spec to be right, and the README tells readers it is.

**Impact:** Before S29, the API description generated by S27 had nothing checking it against the real code, so an inaccuracy could sit there undetected and still be trusted. S29 impact: the app's own build reads that description back and fails if it no longer matches the real data shapes — so the published description cannot quietly drift away from what the server actually sends.

**Why here:** After **S27** (needs the committed spec) and — as of the 2026-09-13 review — **after S25** rather than before it. [ADR-016](./ARCHITECTURE.md#adr-016--generated-client-dal-from-the-openapi-spec-accepted) records the round-trip decision and the fidelity guard that makes it acceptable; this story is now scoped to **that guard**, with the DAL adoption deferred (below).

**Why it moved behind S25 (2026-09-13 review).** ADR-016's own honest accounting says this story "buys exactly one thing: proof that the spec is faithful" — it is a **check on S27's emitter**, not a product capability, and it blocks nothing. S25 blocks eight stories. The original ordering ("before S25, so the cache isn't built on an ingress layer this story would immediately replace") overstated the rework: S25's resource modules derive payload types through `ApiResponseFor`, so the swap is an import change in two files inside this story's existing `web/` fence, not a rewrite.

**Re-decided 2026-09-16 (backlog review) — split, not deferred wholesale.** The standing re-decision the 2026-09-13 review required was carried out against `dafeae8`. Its finding: the two halves of this story have very different value.

- **The guard is the part worth having, and it does not need the DAL.** ADR-016's own accounting says the round-trip "buys exactly one thing: proof that the spec is faithful." That proof is produced by generating *types* from the committed spec and asserting mutual assignability — no `openapi-fetch`, no fetch-layer rewrite. The guard is what makes deferring the rest safe, because it turns "does the wire type space still round-trip losslessly?" from a grep a reviewer has to remember into a compile error.
- **The DAL adoption is the part that buys nothing today, and it is deferred.** `openapi-fetch`, and purging the hand-written route-path literals from `web/src/api/client.ts`, move to the **Generated DAL adoption** Later theme behind a named trigger. There is no external consumer (FEATURES drops public catalog APIs; ADR-016's own "Still open" is exactly whether one ever justifies publishing the spec), and a typed fetch wrapper duplicates what the S26 route key already does for the response type.
- **The prior review's stated risk did not survive contact with the emitter.** It kept this story partly because "68 `| null` unions … nullable representation is exactly where JSON Schema → OpenAPI → TS loses fidelity." At HEAD the emitter represents nullability in OpenAPI 3.1's native forms — `{"type": ["string","null"]}` and `anyOf: [$ref, {"type":"null"}]` — both of which `openapi-typescript` reverses exactly. Expect AC 4 to pass first try; that is the point of the reduced cap, not a reason to skip it.

**Acceptance criteria** (checks `scripts/verify-S29.sh` performs)

1. `web/package.json` depends on `openapi-typescript`. A `package.json` script regenerates the types from the committed spec **with no network** (the grader runs it offline). **`openapi-fetch` is deliberately *not* added** (re-scoped 2026-09-16 — see the Later theme); the script fails if it appears in any manifest.
2. Generated output lives under `web/src/api/generated/`, is committed, and every file there carries an `@generated` banner in its first 5 lines. The script fails if any file in that directory lacks one.
3. **Drift gate:** running the generator produces **no diff** under `web/src/api/generated/` (`git diff --exit-code` on that path). A stale committed artifact fails the story. This regenerate-then-compare check **also runs as a `web/` Vitest test** (in `pnpm verify` / `pnpm test:coverage`'s path), because ADR-016 requires spec→client freshness *enforced in CI* and both `scripts/` and `.github/` are outside this story's fence — the per-story grader is not a CI gate (`ci.yml` runs lint / test:coverage / build only).
4. **Fidelity gate (the load-bearing check):** a type-level test asserts that for **every** route in the S26 table, the generated response type and that route's **`<DomainType>Response` alias** (`GameSnapshotResponse`, `ScheduleDayResponse` — the type actually on the wire) are **mutually assignable** (assignable both directions, not merely compatible one way). `pnpm --filter @bt/web exec tsc -p tsconfig.json --noEmit` exits **0**. This is what catches round-trip fidelity loss; without it the story is not done. **Compare against the alias, not the bare `@bt/domain` type** (amended 2026-09-13): the aliases are structurally identical to their domain types today, so the check is equivalent right now — but asserting against `GameSnapshot` directly would, the day a `to<DomainType>Response` mapping function stops being a passthrough, force the alias back into lockstep with the domain type and destroy the [ADR-014 response-alias seam](./ARCHITECTURE.md#response-aliases--the-dto-seam-accepted-2026-09-13) this gate is supposed to protect.
4a. The gate is proven to have teeth, not just to pass: the same type-level test file contains at least one `@ts-expect-error` case showing a deliberately wrong pairing (e.g. the game route's generated type against `ScheduleDayResponse`) fails assignability. An unnecessary `@ts-expect-error` makes `tsc` fail, so AC 4's exit 0 then proves the assertion is real rather than vacuously satisfied by a widened `any`-ish generated type.
5. **The generated types are load-bearing in shipped code, not only in a test.** **S25's resource modules** (`web/src/api/game.ts`, `web/src/api/schedule.ts`) import their payload types from `web/src/api/generated/` rather than through `ApiResponseFor`, completing the forward obligation S25 AC 3 records; the script greps both files for a `generated/` import and fails if either still routes through `ApiResponseFor`. **Re-scoped 2026-09-16:** the other half of the old AC 5 — purging hand-written route-path literals from `web/src/api/client.ts` and routing fetches through `openapi-fetch` — moved to the **Generated DAL adoption** Later theme. Do **not** rewrite `client.ts`'s fetch layer or `client.test.ts` here.
5a. **Generated code is excluded from the `web` coverage floor, and no threshold is lowered.** `web/vitest.config.ts` excludes `src/api/generated/**` from `coverage.exclude` (or narrows `coverage.include`), and its `lines`/`statements`/`functions`/`branches` numbers are **greater than or equal to** the values at the commit that starts this story. Committed generated output is not ours to test; the correct response is to stop counting it, never to drop a floor to accommodate it. The script compares the config's numbers against the story-start commit and fails on any decrease.
6. Grep of `web/src/api/` **excluding** `generated/` finds no `: any`, `as any`, `any[]`, or `as unknown as`.
7. **No runtime validation** added at this boundary (ADR-014 and ADR-016 both reject it): no `zod` or `valibot` import under `web/src/api/`.
8. `pnpm --filter @bt/web exec vitest run` exits 0 (existing web tests still pass).
9. This file's S29 **Status** (story heading and top table) is `done`.
