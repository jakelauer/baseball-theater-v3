**Gap:** S27 commits `openapi.json` as a derived artifact that **nothing consumes**. `oasdiff` only compares the spec against its own previous self, never against reality — so a route the emitter under-specifies (a dropped field, wrong nullability, a widened union) passes the gate forever and stays wrong. Meanwhile the web client hand-writes its fetch layer against the TS table, so nothing ever forces the spec to be right.

**Impact:** Before S29, the API spec generated by S27 had nothing actually reading it, so an inaccuracy could sit undetected forever. S29 impact: the web app's data-fetching code is generated directly from that spec, so the spec has to stay accurate or the app itself won't build — closing the loop S27 opened.

**Why here:** After **S27** (needs the committed spec) and — as of the 2026-09-13 review — **after S25** rather than before it. [ADR-016](./ARCHITECTURE.md#adr-016--generated-client-dal-from-the-openapi-spec-accepted) records the round-trip decision and the fidelity guard that makes it acceptable.

**Why it moved behind S25 (2026-09-13 review).** ADR-016's own honest accounting says this story "buys exactly one thing: proof that the spec is faithful" — it is a **check on S27's emitter**, not a product capability, and it blocks nothing. S25 blocks eight stories. The original ordering ("before S25, so the cache isn't built on an ingress layer this story would immediately replace") overstated the rework: S25's resource modules derive payload types through `ApiResponseFor`, so the swap is an import change in two files inside this story's existing `web/` fence, not a rewrite. Weighed against that, the round-trip risk is concrete: `packages/domain/src/types.ts` + `plays.ts` carry **68 `| null` unions** across the two response payloads, and nullable representation is exactly where JSON Schema → OpenAPI → TS loses fidelity — so AC 4 failing into "stop and report, that is S27's bug" is a realistic outcome that should not be able to strand the carried loop.

**Standing re-decision.** The review immediately before this story starts must re-confirm it still earns its cap given what S27 actually shipped — deferring it to a "when an external consumer is real" trigger is a live option (see [Backlog reviews](#backlog-reviews)).

**Acceptance criteria** (checks `scripts/verify-S29.sh` performs)

1. `web/package.json` depends on `openapi-typescript` and `openapi-fetch`. A `package.json` script regenerates the DAL from the committed spec **with no network** (the grader runs it offline).
2. Generated output lives under `web/src/api/generated/`, is committed, and every file there carries an `@generated` banner in its first 5 lines. The script fails if any file in that directory lacks one.
3. **Drift gate:** running the generator produces **no diff** under `web/src/api/generated/` (`git diff --exit-code` on that path). A stale committed artifact fails the story. This regenerate-then-compare check **also runs as a `web/` Vitest test** (in `pnpm verify` / `pnpm test:coverage`'s path), because ADR-016 requires spec→client freshness *enforced in CI* and both `scripts/` and `.github/` are outside this story's fence — the per-story grader is not a CI gate (`ci.yml` runs lint / test:coverage / build only).
4. **Fidelity gate (the load-bearing check):** a type-level test asserts that for **every** route in the S26 table, the generated response type and that route's **`<DomainType>Response` alias** (`GameSnapshotResponse`, `ScheduleDayResponse` — the type actually on the wire) are **mutually assignable** (assignable both directions, not merely compatible one way). `pnpm --filter @bt/web exec tsc -p tsconfig.json --noEmit` exits **0**. This is what catches round-trip fidelity loss; without it the story is not done. **Compare against the alias, not the bare `@bt/domain` type** (amended 2026-09-13): the aliases are structurally identical to their domain types today, so the check is equivalent right now — but asserting against `GameSnapshot` directly would, the day a `to<DomainType>Response` mapping function stops being a passthrough, force the alias back into lockstep with the domain type and destroy the [ADR-014 response-alias seam](./ARCHITECTURE.md#response-aliases--the-dto-seam-accepted-2026-09-13) this gate is supposed to protect.
4a. The gate is proven to have teeth, not just to pass: the same type-level test file contains at least one `@ts-expect-error` case showing a deliberately wrong pairing (e.g. the game route's generated type against `ScheduleDayResponse`) fails assignability. An unnecessary `@ts-expect-error` makes `tsc` fail, so AC 4's exit 0 then proves the assertion is real rather than vacuously satisfied by a widened `any`-ish generated type.
5. `web/src/api/` consumes the generated client: **no** hand-written route path literal (`"/api/v1/`) appears anywhere under `web/src/` outside `web/src/api/generated/`. **S25's resource modules** (`web/src/api/game.ts`, `web/src/api/schedule.ts`) import their payload types from `web/src/api/generated/` rather than through `ApiResponseFor`, completing the forward obligation S25 AC 3 records; the script greps both files for a `generated/` import and fails if either still routes through `ApiResponseFor`.
5a. **Generated code is excluded from the `web` coverage floor, and no threshold is lowered.** `web/vitest.config.ts` excludes `src/api/generated/**` from `coverage.exclude` (or narrows `coverage.include`), and its `lines`/`statements`/`functions`/`branches` numbers are **greater than or equal to** the values at the commit that starts this story. Committed generated output is not ours to test; the correct response is to stop counting it, never to drop a floor to accommodate it. The script compares the config's numbers against the story-start commit and fails on any decrease.
6. Grep of `web/src/api/` **excluding** `generated/` finds no `: any`, `as any`, `any[]`, or `as unknown as`.
7. **No runtime validation** added at this boundary (ADR-014 and ADR-016 both reject it): no `zod` or `valibot` import under `web/src/api/`.
8. `pnpm --filter @bt/web exec vitest run` exits 0 (existing web tests still pass).
9. This file's S29 **Status** (story heading and top table) is `done`.

- Fixing the emitter. If the fidelity gate in AC 4 fails because the spec genuinely under-specifies a route, that is **S27's** bug — stop and report it rather than patching the generated output or loosening the assertion.
