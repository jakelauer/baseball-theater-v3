**Gap:** ADR-026: at most 200 KB gzipped JavaScript before the page is usable, render-count baselines for heavy views, and coverage floors of 95% (domain) and 85% lines / 80% branches elsewhere. The owner chose to ratchet (2026-10-19): floors go to today's measured values now and every story raises them until the targets are met by the end of the UI band. Measured at HEAD by the reviewers: domain 94.5% lines / 79.5% branches, web 48.5% / 85%, functions 80% / 78%; floors are far lower (web lines 14). No `size-limit`. At `58db7c2` the web build is one entry chunk of 143,833 bytes gzipped (~140 KB), so the 200 KB budget holds with ~60 KB of headroom; `tools/` (S52's lint-rule tests) is not a workspace package and has no coverage floor, so AC 3's "every package" means `packages/*`, `functions` and `web`. **Re-measured at `1967ae3` (2026-10-20 backlog review):** lines / branches / functions / statements: domain 95.95 / 87.5 / 94.28 / 95.95 (already at the 95 target), mlb-api 100 / 88.05 / 100 / 100, functions 80.01 / 78.21 / 87.77 / 80.01, web 47.35 / 84 / 69.81 / 47.35; one entry chunk of 143,827 B gzipped. `packages/ports` is interfaces only: no runtime code, no tests and no coverage block (v8 reports 0% lines for its re-export `index.ts`), so AC 3's floors apply to the packages with runtime code and ports stays without one. **AC 1's 1 KB test cannot read `web/dist`:** `pnpm verify` runs `test:coverage` before `pnpm build`, so on a clean checkout (CI) there is no `dist` yet. The test runs `size-limit` on a temp file instead, under `tools/` like S53's `jscpd` test (picked up by `pnpm test:tools`), and `pnpm verify` runs `size-limit` after `pnpm build`; `tools/` was added to the fence for it. Inserted by the 2026-10-19 design intake review (two independent fresh-context reviewers, merged).

**Impact:** Before S54, the app could get heavier and the tests could cover less without anyone noticing. S54 impact: the build fails when the app's code outgrows its size budget or test coverage slips, and slow-to-redraw screens can be measured.

**Source:** Pillar: Dependable — the gates ADR-024–026 require, so duplicated logic, stale comments, slow pages and thin tests are caught by a check rather than by users. Asked whether the guardrail and budget stories may cite Dependable, as S49 does. Approved by owner 2026-10-19: "Yes"
