**Gap:** BT has every pitch of the games it records (`GameSnapshot.plays`: type, call, count, location, kinematics) but nothing that learns from them. Inserted by the owner, 2026-10-29: *"I want to make a story to use pitch data to train a model or a fine tune to predict the next pitch during games"*; asked how, the owner chose *"Train our own small model"* over an LLM fine-tune.

**Impact:** Before S90, BT can only show pitches after they're thrown. S90 impact: BT has a model that, given the game situation, gives the odds of each pitch type and where it's likely to go — and a measured answer to whether it beats simply guessing the pitcher's usual pitch.

**Source:** Feature: Next-pitch prediction

**Acceptance criteria** (checks `scripts/verify-S90.sh` performs)

1. **An ADR for the model** is proposed in `docs/v3/ARCHITECTURE.md` and accepted by the owner (quoted): where training runs (offline, on a developer machine or CI — never on a request), the training toolchain (inside the locked TypeScript stack, or the case for an exception), the model's file format, and how the Worker evaluates it with no ML runtime of its own (e.g. trees or weights evaluated in plain TypeScript).
2. **Training data** comes from MLB's own pitch-by-pitch recordings via the existing ingest path, never scraped pages: `pnpm pitch-model:collect` records past seasons offline (`BT_USE_LIVE_MLB=1`), folds them with the S63 replay fold, and writes one row per pitch — features known *before* the pitch (pitcher, batter side, count, outs, runners, inning, score margin, the pitcher's previous pitches in the at-bat and his season mix so far) and the label (pitch type, plate location). A small committed sample under `fixtures/pitch-model/` keeps tests offline.
3. **No future leaks into a prediction:** a test shows every feature for pitch *n* is computed from pitches before *n* only, and training / test splits are by date (train on earlier games, test on later ones).
4. **The model** is one named, tested function in `packages/domain` (`predictNextPitch(situation, model) → { types: { type, probability }[]; location: { pX, pZ, spread } }`): pitch-type probabilities sum to 1; the location is a likely spot with its spread.
5. **An honest evaluation** in `scripts/pitch-model/eval.md`, regenerated by `pnpm pitch-model:eval` on the held-out games: log loss and top-1 accuracy for pitch type, and location error, each beside the **baseline** of the pitcher's own pitch mix in that count. The script fails if the model doesn't beat the baseline on pitch type.
6. The model file is small enough to ship to the Worker (target under 1 MB) and `predictNextPitch` runs in under a millisecond per pitch (timed in the test).
7. This file's S90 **Status** (story heading and top table) is `done`.
