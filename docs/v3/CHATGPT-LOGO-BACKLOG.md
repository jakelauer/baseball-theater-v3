# MLB Team Identifier Design Tracker

## Purpose

This document is the persistent design record for the MLB Team Identifier Icon System.

The goal is to create original visual identifiers for all 30 MLB teams that:

- Are recognizable enough that an MLB-familiar viewer can make a good guess at the team
- Use the team's recognizable color scheme as a major recognition cue
- Work at very small scoreboard sizes, approximately 16-32 px
- Prefer strong and distinctive silhouettes
- Use simple, bold geometry
- Feel like members of one coherent icon system
- Are independently designed rather than modified versions of existing MLB/team logos

This document records decisions made during the design process so future team concepts can take previous work into account.

---

# System-Level Design Principles

## Priority Order

When design considerations conflict, use this priority order:

1. Team recognition
2. Recognizable team color scheme
3. Strong, distinctive silhouette
4. Small-size legibility
5. Simple, bold geometry
6. Conceptual connection to the team's identity
7. Consistency with the overall icon system
8. Fine detail and ornamentation

## Recognition

The icon should give a viewer a reasonable chance of identifying the team without relying on text.

Recognition can come from:

- Team colors
- A distinctive silhouette
- A conceptual association with the team
- City/geographic associations
- Mascot or animal associations
- Historical identity
- Secondary visual motifs
- Abstract geometry inspired by, but not reproducing, the team's identity

The team's existing primary logo does not have to be the source of the icon's concept.

## Small-Size Requirements

Design for the final use case first.

Icons should:

- Remain legible at approximately 16-32 px
- Use large shapes rather than fine lines
- Have strong contrast
- Avoid tiny internal details
- Avoid intricate typography
- Avoid texture-dependent recognition
- Have a meaningful outer silhouette when possible
- Ideally remain recognizable when viewed as a monochrome silhouette

## Color

Use recognizable current team colors as a major recognition cue.

White, black, and neutral tones may be used where necessary for contrast.

Color should generally reflect the team's current visual identity, but exact Pantone matching is unnecessary during concept development unless specifically requested.

## System Consistency

The icons should feel like members of the same scoreboard icon system.

Consistency should come primarily from:

- Similar visual weight
- Similar level of abstraction
- Similar simplicity
- Similar small-size performance
- Clean vector-like execution

The icons do NOT need to use identical construction.

Do not force every team into:

- A circle
- A shield
- A monogram
- A badge
- The same internal layout

If a team has a particularly strong alternative silhouette, use it.

---

# Originality Requirements

The purpose of the system is to create original team identifiers rather than reproductions of MLB/team marks.

Do NOT:

- Trace an existing logo
- Recreate an existing logo with minor changes
- Change only the colors of an existing logo
- Rotate, mirror, distort, simplify, or geometrically manipulate an existing logo
- Reproduce distinctive team lettering or monograms
- Add a generic circle, shield, or badge around an existing logo
- Remove details from an existing logo while retaining its recognizable structure
- Create a symbol whose structure is essentially the existing logo with superficial modifications

Instead:

- Use the team's broader visual identity as inspiration
- Identify multiple recognizable elements of the team
- Construct a new symbol from independent geometric or conceptual elements
- Prefer secondary identity cues when the primary logo is too distinctive to safely abstract
- Use team colors heavily to reinforce recognition

The intended test is:

> If the original team logo were placed beside the proposed icon, the icon should clearly look like a different piece of graphic design rather than an altered version of the logo.

---

# Concept Generation Process

For each team:

1. Research and analyze the team's current and historically recognizable visual identity.
2. Identify the strongest recognition cues.
3. Identify which cues can safely inspire an original symbol.
4. Generate four substantially different concepts.
5. Render them as a clean 2×2 grid.
6. Present the four concepts for selection.
7. Iterate on the selected concept.
8. Produce a clean final icon.
9. Record the result in this document.
10. Record distinctive visual vocabulary that should not be unnecessarily reused for other teams.

## Four Concepts

The four concepts should represent meaningfully different design strategies.

Possible strategies include:

- Abstract geometric symbol
- Distinctive silhouette
- Negative-space symbol
- Architectural/geographic reference
- Mascot or object silhouette
- Abstracted secondary identity element
- Baseball-related geometry
- Abstract monogram-like geometry that does NOT reproduce the actual team monogram
- Symbol derived from team history
- Symbol derived from city or regional identity

Do not create four minor variations of the same concept.

---

# Concept Grid Requirements

Each concept sheet should be rendered as a clean 2×2 grid.

The four concepts should:

- Have approximately equal visual weight
- Be large enough to inspect
- Use flat, clean, vector-like geometry
- Use recognizable team colors
- Have strong silhouettes
- Avoid unnecessary text
- Avoid gradients
- Avoid photorealism
- Avoid textures
- Avoid shadows
- Avoid visual clutter
- Be clearly separated from one another
- Be designed with tiny scoreboard use in mind

The artwork itself is the primary output.

Concept labels may be provided separately or minimally beneath each concept.

---

# Iteration Process

After the four concepts are presented, wait for the user to select one.

If the user selects a concept:

- Treat that concept as the starting point
- Preserve its core recognition mechanism unless the user requests otherwise
- Make requested adjustments
- Refine geometry rather than restarting unnecessarily
- Produce a clean final version when approved

If the user rejects all four:

- Identify what failed
- Avoid repeating the rejected approach
- Generate four genuinely different concepts

If the user asks for additional concepts:

- Explore new conceptual directions
- Do not merely change colors
- Do not make only minor geometric variations

## Recurring Geometric Motifs

Track particularly distinctive uses of:

- Circular badges
- Rings
- Stars
- Diamonds
- Arcs
- Radial geometry
- Compass geometry
- Crosses

- Abstract monograms

- Typography-derived geometry

A motif may be used by multiple teams when appropriate, but avoid making the same motif the primary recognition mechanism for several teams.
